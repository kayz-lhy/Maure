# Maure 技术选型决策

## 语言与基础设施

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 开发语言 | Go | 实现简洁、部署成本低、性能可控 |
| 依赖管理 | Go Modules | 官方标准，维护成本低 |
| 测试框架 | `testing` 标准库 | 降低依赖复杂度 |
| 静态检查 | `go vet` | 官方检查，适合当前规模 |

## CLI 与接口

| 决策项 | 选择 | 理由 |
|--------|------|------|
| CLI 解析 | Cobra | 命令树清晰、可扩展、help 体验一致 |
| 兼容策略 | 双轨兼容 + deprecate warning | 降低迁移成本，避免脚本立即失效 |
| HTTP 服务 | 标准库 `net/http` | 轻量、依赖少、可控 |

## 索引与存储

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 内存检索结构 | RAMIndex + InvertedIndex | 查询路径直接、易调试 |
| 持久化 | FSDirectory + Snapshot + WAL | 实现简单且具备基本可靠性 |
| 快照格式 | gob 编码（可扩展字段） | 兼容旧结构成本低 |

## 查询与评分

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 查询解析 | 自研 QueryParser | 可控性高，便于演进 |
| 评分算法 | BM25 + TF-IDF | 覆盖常见检索场景 |
| 聚合 | 轻量 `count/group` | 满足日志场景核心诉求 |

## 并发与一致性

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 内存并发控制 | `sync.RWMutex` | 易理解、读多写少场景适配 |
| 持久化提交模型 | WAL 先写，Commit 生成快照 | 在简单模型下提供崩溃恢复能力 |

## 已识别技术债

1. `/search` 的 Top-N 约束需要在查询执行层真正生效。
2. 前端示例存在 N+1 文档详情请求模式。
3. 复杂布尔查询分配开销偏高。

详见：`docs/reports/search-api-performance-analysis.md`。
